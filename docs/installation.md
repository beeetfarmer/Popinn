## Requirements

| | |
| --- | --- |
| Container runtime | Docker 24+ or Podman 4+, with the Compose plugin |
| Disk | Your media, plus roughly 2–5% of its size for thumbnails, previews and HLS output |
| Memory | 4 GB for the backend under the default `BACKGROUND_WORKERS=4`; see [Resource limits](#resource-limits) |
| CPU | Any x86-64 or arm64 machine. Transcoding is CPU-bound, so more cores means faster HLS generation |

`ffmpeg` and `ffprobe` ship inside the backend image — you do not need them on
the host.

## Choosing a compose file

Three compose files are included, and they differ only in where the images come
from and how much they trust the host.

| File | Images | Use it when |
| --- | --- | --- |
| `docker-compose.yml` | Pulled from Docker Hub | Normal self-hosting. This is the one you want. |
| `docker-compose.prod.yml` | Built locally from source | You want to run your own build, or you are changing the code |
| `docker-compose.dev.yml` | Built locally, with hot reload | Active development — see [Development](development.md) |

All three read a single `.env` file, so you configure once and switch freely.

## First run

```bash
git clone https://github.com/beeetfarmer/Popinn.git
cd Popinn
cp .env.example .env
```

Set the mandatory values in `.env`:

```ini
# Both must be long and random. Nothing else in the file matters as much.
POSTGRES_PASSWORD=...
SECRET_KEY=...

# Absolute path to your music videos on the host. Mounted read-only.
POPINN_MEDIA_PATH=/srv/media/music-videos

# Where Popinn writes thumbnails, previews and transcodes.
POPINN_APPDATA_PATH=./app-data

# The port the web UI listens on.
WEB_PORT=8080
```

Generate secrets with:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Start the stack:

```bash
docker compose --env-file .env -f docker-compose.yml up -d
```

Database migrations run automatically on backend startup, so there is no
separate init step. Watch it come up with:

```bash
docker compose -f docker-compose.yml logs -f backend
```

Then open `http://localhost:8080`, register the first account (it becomes
administrator), and run **Settings → Scan Library**.

Once you have your accounts, close registration:

```ini
ALLOW_PUBLIC_REGISTRATION=false
```

Administrators can still create users from the settings page.

## Storage layout

Two host directories matter.

**Media** (`POPINN_MEDIA_PATH`) is mounted **read-only**. Popinn never writes to
it, never renames your files, and never deletes them. Deleting a video in the UI
marks the database row deleted and leaves the file alone.

**App data** (`POPINN_APPDATA_PATH`) is where everything Popinn generates lives:

```
app-data/
├── .thumbnails/     JPEG stills, one per video
├── .previews/       short muted clips for hover previews
├── .hls/            transcoded HLS output: <video-uuid>/index.m3u8 + segments
├── .artist-images/  uploaded and fetched artist artwork
└── .user-images/    uploaded profile pictures
```

Everything here is derived and can be regenerated by rescanning — but
regenerating HLS means re-transcoding, which is slow. Back it up if you would
rather not redo that work.

> Video IDs are regenerated if you ever wipe the database and rescan, which
> orphans the old `.hls/<uuid>/` directories. They are harmless but they do
> consume disk; deleting directories whose UUID no longer matches a video is
> safe.

## File permissions

The backend image runs as UID 10001, and whether that UID can write to your
app-data directory depends on your runtime. This is the single most common
cause of a failed first run.

**Rootless Podman** maps container UID 10001 to an unprivileged subordinate UID
that has no access to your files, so every thumbnail write fails with `EACCES`.
Fix it by remapping to your own user:

```ini
POPINN_USERNS=keep-id:uid=10001,gid=10001
```

This keeps the container non-root *and* makes it able to write.

**Docker** does not understand `keep-id` and will refuse to start if you leave
it set. Clear it and hand the directory to the image's user once:

```ini
POPINN_USERNS=
```

```bash
mkdir -p ./app-data && sudo chown -R 10001:10001 ./app-data
```

**Rootless Docker** — leave `POPINN_USERNS=` empty as above, but `chown` to the
subordinate UID that maps to 10001 inside your user namespace.

## Resource limits

The backend's memory and CPU allowances scale with `BACKGROUND_WORKERS`,
because each worker can be holding an `ffmpeg` transcode.

```ini
BACKGROUND_WORKERS=4
POPINN_BACKEND_MEMORY=4g
POPINN_BACKEND_CPUS=4
```

Budget roughly **0.5 GB and 1 CPU per worker**. Measured with four workers
transcoding concurrently, the backend sits around 1.8 GB resident.

Transcoding is capped at 1080p and four encoder threads per job. Without those
caps a 4K source is re-encoded at 4K, and a single job can hold ~2.7 GB — enough
to OOM-kill the container when several run at once.

If your machine is small, lower `BACKGROUND_WORKERS` before lowering the memory
limit. Scans and transcodes will take longer but will not be killed.

## Reverse proxy and HTTPS

The `web` container terminates plain HTTP on `WEB_PORT`. For internet-facing
deployments put a TLS-terminating proxy in front of it.

Whatever hostname you serve on must be listed in `ALLOWED_HOSTS`, or FastAPI's
`TrustedHostMiddleware` rejects the request:

```ini
ALLOWED_HOSTS=popinn.example.com,localhost,127.0.0.1
ALLOWED_ORIGINS=https://popinn.example.com
COOKIE_SECURE=true
```

Keep `COOKIE_SECURE=true` anywhere you have HTTPS. Set it to `false` **only**
for plain-HTTP LAN access, since browsers refuse to store `Secure` cookies over
HTTP and you will not be able to log in.

Your proxy must forward large range requests unbuffered for video seeking to
work. A minimal nginx location block:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    client_max_body_size 16m;
}
```

## Upgrading

```bash
docker compose --env-file .env -f docker-compose.yml pull
docker compose --env-file .env -f docker-compose.yml up -d
```

Migrations run automatically on startup. To pin a specific release rather than
tracking `latest`, set `TAG` in `.env`:

```ini
TAG=0.1.0     # exact release
TAG=0.1       # newest 0.1.x patch
TAG=latest    # newest build
```

Back up the database before upgrading across a minor version.

## Backups

**The database is the only thing that is genuinely irreplaceable** — it holds
your users, watchlists, play history and metadata edits.

```bash
docker compose -f docker-compose.yml exec -T db \
  pg_dump -U popinn popinn | gzip > popinn-$(date +%F).sql.gz
```

Restore into a running, empty stack:

```bash
gunzip -c popinn-2026-01-01.sql.gz | \
  docker compose -f docker-compose.yml exec -T db psql -U popinn -d popinn
```

Also keep `.env` somewhere safe: losing `SECRET_KEY` invalidates every session
and every issued token, and losing `POSTGRES_PASSWORD` locks you out of your own
database.

`app-data/` is optional to back up. Everything in it regenerates, though HLS
transcodes take real time to rebuild.
